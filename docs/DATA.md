# Данные: автоматический сбор POI Астаны

По условию задачи датасет собирает команда, и сбор должен быть автоматизирован. Весь процесс запускается одной командой:

```bash
cd backend
uv run python -m pipeline.cli all     # fetch → build → graph → embed → events
# или по шагам: fetch | build | graph | embed --model e5-large | events
```

Еженедельно сбор повторяет GitHub Actions ([`.github/workflows/data-refresh.yml`](../.github/workflows/data-refresh.yml)) и открывает PR с новым снимком. Снимок `data/processed/` закоммичен в репозиторий, поэтому демо не зависит от внешних API: Overpass в день разработки несколько часов отвечал ошибками 502/504.

### Почему без 2ГИС (решение от 20.10)
Участник команды собрал с публичного сайта 2ГИС срез по Астане (часы, рейтинги, фото). Мы попробовали его как отдельный слой и **отказались**: лицензия на сайт и приложения 2ГИС (§6.1.1, §6.2) запрещает извлекать справочные данные, а правила API запрещают хранить и кэшировать полученное. Слой и его сборщик удалены, продукт не хранит и не показывает данные 2ГИС. В тот же день из репозитория убраны и следы сбора каталога 19.10: архивы `data/review/2026-10-19-*` и `eval/runs/2026-10-19-*`, выгрузка `place_details_discovery`, а из рабочего среза каталога (`data/processed/current`) и `place_details_2026-10-19.json` — около 2900 фактов, цен и подтверждений филиалов со ссылкой на 2ГИС. Четыре места, которые 19.10 были исключены по карточке 2ГИС (три закрытых филиала и лотерейный клуб), остаются исключёнными: это осторожная сторона, но сама карточка больше не хранится. В истории git эти файлы остаются. Часы работы — только из открытых и официальных источников: OpenStreetMap (свежий запрос — `python -m pipeline.osm_hours`), официальные сайты сетей и мест (`python -m pipeline.site_hours`: цитата со страницы обязательна; и исследование 20.10 по официальным сайтам, `wave3_batch_*`), CityPass, AllThePlaces (CC0), а также карточки Sxodim со ссылкой (см. таблицу). Это ~26% мест; у остальных честно «часы неизвестны». На каждой карточке остаётся кнопка «Открыть в 2ГИС», где человек видит актуальные часы сам.

### Что сознательно не используем
- **Google Places, Yandex.** Их условия запрещают хранить и кэшировать данные, а Google запрещает передавать данные в LLM и показывать их на не-гугловой карте. Подробнее в [RESEARCH.md](RESEARCH.md).
- **Автоматический скрейпинг Google Maps и т.п.**
- **Тексты visitastana.kz.** На сайте «все права защищены».

## Как собирается POI

1. **Категория.** Теги OSM переводятся в одну из 33 категорий ([`app/categories.py`](../backend/app/categories.py)). Для каждой категории заданы: группа, в помещении или на улице, типичное время визита, подходит ли детям, только 18+ или нет, ночная ли это активность. Закрытые места (`disused:*`, `was:*`, `opening_hours=closed`) отбрасываются. Экспонаты, нанесённые внутри зданий (`tourism=attraction` + `indoor`), тоже.
2. **Дубли.** Точка и контур одного и того же места объединяются: та же категория, похожее имя, расстояние меньше 120 м.
3. **Подписи без названий.** 282 детские площадки и часть скверов в OSM без названия. Они получают подпись по ближайшему парку (до 300 м), ЖК (до 250 м) или улице (до 200 м), например «Детская площадка (Нұржол желекжолы)». Флаг `name_auto` сохраняется.
4. **Wikidata.** Сопоставляется по тегу `wikidata`, иначе по имени в радиусе 300 м. Сравнение имён строгое (`textnorm.same_name`): короткое имя должно покрывать большую часть длинного, название города не учитывается, двуязычные «А / B» и пояснения в скобках разбираются. Раньше `token_set` считал «Jasmine Coffee room Astana» равным «Астане», и кафе получало статью о городе — это нашли тесты Аслана. Теперь города, районы и регионы Wikidata не сопоставляются с местами вовсе, а кафе не получает статью о ТРЦ с тем же именем (проверка совместимости категорий). Объект того же типа в пределах 40 м считается тем же местом («Парк Влюбленных» = «Ғашықтар саябағы»). Несопоставленные достопримечательности добавляются как новые POI.
5. **Wikipedia.** Описание по QID: сначала русская статья, потом английская; если статьи нет в геопоиске — по ссылкам Wikidata (ru → kk → en). У каждого описания есть ссылка, заголовок и `description_license = "CC BY-SA 4.0 · Wikipedia contributors"`.
6. **Overture.**
   - Фильтры: confidence ≥ 0.6; отбрасываются «стопки», когда 3 и больше мест стоят в одной точке (геокодированы в центроид); отбрасывается `historic_site` (на деле это в основном ЖК).
   - Отбрасываются «имена», которые на деле домен или адрес («gorkytheatre.kz», «ул. Абылай хана 5/2»).
   - Совпадение с OSM: до 150 м и строгое совпадение имени; либо до 60–100 м, если одно имя — другое плюс описание («ПИНТА Bar & Grill» = «Пинта»); либо тот же тип места в 40 м. Тогда OSM остаётся главной записью, Overture добавляет контакты.
   - **Карантин** (`data/quarantine.json`): записи, которые мы проверили и признали ошибочными, с причиной (ресторан с названием-адресом, вокзал с типом «бар», Overture-дубль закрытого в OSM места).
   - **CityPass** (из командного сбора): если место уже есть, добавляются часы (`hours_source`) и ссылка; новые записи принимаются только для музеев и впечатлений. Ошибки геокодинга источника отсеиваются: сфера Нур Алем (теперь Alem.AI) стояла на месте ТРЦ Ailand — координата исправлена; колесо обозрения и «Джунгли» Ailand стояли у Хан Шатыра — пропущены.
7. **Описание**, если нет живого текста: шаблон только из фактов тегов, например «Кофейня / кафе. Кухня: кофе. Удобства: Wi-Fi, летняя веранда. Адрес: …». Без выдуманных деталей, с пометкой `description_source=template`.
8. **Популярность** (рейтингов в открытых данных нет): `0.45·log(языковые версии Wikidata) + 0.35·log(просмотры Wikipedia) + 0.2·полнота данных`.
9. **Газеттир для «Я возле…».** Названия всех POI и ЖК, вокзалы, аэропорт, стадионы, университеты из Overture, 861 точка из командного сбора (285 отелей с русским написанием латинских имён: «Hilton» → «хилтон», вузы, больницы, госорганы) и 27 вручную описанных ориентиров с алиасами на RU/KK/EN («Mega Silk Way / мега силк», «Бәйтерек», «әуежай»). Сопоставление строгое по типу объекта, чтобы кафе «Astana Arena» не стало стадионом.
10. **Пешеходный граф.** osmnx `network_type="walk"` экспортируется в массивы numpy (CSR + геометрия рёбер, 1.7 МБ). Во время работы API нужен только scipy.
11. **Эмбеддинги.** `multilingual-e5-large` (int8 ONNX) с префиксом `passage:`, float16, ~4.7 МБ. Это индексация готовой модели, а не обучение.

Для 25 ориентиров заданы такие варианты с падежами; «старая Мега» (ТРЦ «Мега Центр Астана») — отдельный ориентир, чтобы не путать её с Mega Silk Way. Варианты применяются при загрузке, без пересборки данных; короткое имя не цепляет другие слова («мега» ≠ «мегафон»).

## Известные ограничения данных
- **Часы работы** заполнены примерно у четверти мест; часть из них — со старых карточек Sxodim (старше года — «низкая» уверенность). «Высокая» уверенность — только у часов с источником, ссылкой и датой (официальные сайты, проверенные исследования); часы из OSM без даты проверки показываются с «низкой». У часов из исследования действует и его собственная оценка: карточка Sxodim датируется днём своей последней правки, а не днём, когда мы её прочитали, и старая карточка остаётся «низкой»; часы всей сети без подтверждения филиала — не выше «средней».
- **Рейтингов нет:** ни один открытый источник их не даёт, поэтому `rating` всегда `null`.
- **Розетки и «тишина»** в OSM почти не отмечаются. Система прямо об этом предупреждает.
- **Описания:** живой текст из Википедии есть только у ~40 крупных достопримечательностей. У остальных описание собрано из тегов.
- **Командный сбор `big-data`** содержит 14 009 мест, но 11 248 из них — магазины, банки, остановки и т.п. Из 2761 «досуговых» 1838 у нас уже есть; остальное в основном спортзалы и записи Overture, которые мы отсеиваем фильтрами уверенности. Поэтому берём из него только факты CityPass и точки отсчёта.
- **Пешеходный граф** покрывает центр, ЭКСПО и НУ. Окраины и аэропорт считаются по формуле, в ответе есть пометка.

## Проверенные факты по самым частым местам (19.10)
1. `backend/pipeline/top_places.py` прогоняет сетку типичных запросов (16 желаний × 11 точек старта по Астане × день/вечер, 352 запроса и готовые маршруты) и выбирает 150 мест, которые система советует чаще всего (`data/sources/place_research/top_places.json`).
2. Шесть ИИ-агентов-исследователей проверили по 25 мест каждый. Разрешённые источники: Википедия, официальные сайты, CityPass, официальные городские сайты, Ticketon, новости (только об открытии или закрытии). 2GIS, Яндекс, Google и TripAdvisor не использовались. Результаты лежат в `data/sources/place_research/batch_*_output.json`, у каждого факта есть ссылка.
3. `python -m pipeline.place_facts data/sources/place_research/batch_*_output.json` проверяет факты:
   - у каждого обязательна ссылка на источник;
   - часы должны разбираться парсером API; часы из Википедии и часы кассы не принимаются;
   - тексты с низкой уверенностью отбрасываются.

   Итог: `data/processed/place_facts.json` — 52 описания своими словами, 11 официальных часов (проверено 19.10), особенности у 9 мест, 1 сносимое место (больше не советуется).
4. API применяет слой при загрузке: описание показывается со ссылкой на источник, часы — с источником и датой проверки, поэтому их уверенность «высокая».
5. Вторая волна (19.10, вечер): 93 места, у которых не было часов или часы вызывали сомнения, проверены ещё четырьмя агентами по тем же разрешённым источникам (`data/sources/place_research/leads_batch_*_output.json`). Часы, взятые только из поискового сниппета или противоречащие друг другу, не принимаются. Итог слоя фактов: 86 мест — 76 описаний, 17 подтверждённых часов, особенности у 21 места.
6. Проверка ссылок (`link_check_2026-10-19.json`): 9 сайтов убраны из карточек. Один домен теперь ведёт на онлайн-казино, другой — на чужой бизнес в Алматы, остальные не существуют или пустые.
7. Названия на трёх языках (`make names`, `python -m pipeline.place_names`). В открытых данных место обычно названо на одном языке, а `name:ru` / `name:kk` / `name:en` есть только у четверти мест. Модель переводит недостающие названия пачками: бренды и латинские названия не меняются, ориентиры получают официальные имена (Бәйтерек / Baiterek), личные имена транслитерируются. Каждый перевод проверяется: нужный алфавит, разумная длина, никаких казахских букв в русском варианте. Названия из OSM всегда важнее перевода, автоматические подписи скверов и площадок не переводятся. Итог: `data/processed/place_names.json` (1 882 места и 27 ориентиров) и `place_descriptions_kk.json` (76 проверенных описаний на казахском, цифры совпадают с русским текстом). Карточка, старт и сводка маршрута показываются на языке пользователя.
