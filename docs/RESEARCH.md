# Исследование перед разработкой: как выбирали стек и подход

До того как писать код, 10 исследовательских агентов параллельно изучили тему. Они делали замеры руками и читали источники за 2025–2026 годы. Ниже решения и цифры, на которых они основаны.

| # | Вопрос | Решение | Ключевые доказательства |
|---|---|---|---|
| 1 | Открытые данные POI | OSM (по границе города) + Overture + Wikidata/Wikipedia | OSM: 1290 именованных мест. Overture: 8481 место, но 13.5% «стопками» в одной точке и ни часов, ни рейтингов. Совпадение с OSM лишь 31% → хорошо дополняет. Foursquare OS Places закрыт и уже входит в Overture |
| 2 | Коммерческие источники (2GIS, Google, Yandex) | Не храним и не используем в промпте | 2GIS: хранение и кэширование запрещены, штраф до 3 млн ₽. Google: нельзя рядом с не-гугловой картой и нельзя передавать в LLM. Yandex: запрещено переупорядочивать выдачу |
| 3 | События и контекст | Ticketon + Sxodim (JSON-LD), Open-Meteo, `holidays`, `astral` | robots.txt разрешает. У Ticketon 5 из 8 площадок имели координату-заглушку → сопоставляем с нашими POI. 26.10.2026 — перенесённый выходной (День Республики), библиотека часов этого не знает |
| 4 | Архитектура RAG | Сначала структура (код), потом гибридный поиск, LLM только выбирает и объясняет | Otsuka 2026 (ISPRS), ~1000 POI: структурный + вектор 89 баллов против 60 у чисто векторного; агентный подход самый медленный. TravelPlanner: LLM без проверок соблюдает ограничения в 0.6% случаев. ITINERA: 0 выдуманных мест, если выбор идёт из кандидатов |
| 5 | Эмбеддинги RU/KK/EN | `multilingual-e5-large` int8 ONNX, локально | Мини-бенчмарк из 32 запросов: Hit@3 = 1.00 (KK 1.00). OpenAI `text-embedding-3-small/large`: KK 0.64 / 0.45. ~1 ГБ RAM, 22 мс на запрос |
| 6 | Бэкенд | Python 3.13 + FastAPI + Pydantic v2, данные в памяти | Прототип на 5000 POI: поиск 7–11 мс, RSS ~200 МБ (без e5). Векторная БД при таком объёме не нужна |
| 7 | OpenAI | `gpt-6-luna`, `reasoning: none`, Responses API, strict JSON, `store=false` | Проверено на ключе: медиана 2.5 с (fast tier 1.7 с), ~$0.00015 за вызов, хороший казахский. `gpt-6.1-sol` 12–43 с, слишком медленно. `gpt-4o-mini` отвечал на KK по-русски. Схема должна быть фиксированной: динамический enum дал всплеск 14.6 с |
| 8 | Маршруты | Свой граф улиц (osmnx → numpy) + scipy Dijkstra | ~3 мс на маршрут, ~250 МБ. Совпадение с OSRM 0.998. **Есиль:** через реку путь в 2–3 раза длиннее прямой. Публичный OSRM игнорирует пешеходный профиль |
| 9 | Продукт | «Ближайшие 30–120 минут» вместо «ещё одной карты»: погода, часы, дедлайн, прозрачность | Google Ask Maps только на английском. 2GIS ищет «по вайбу», но не учитывает время, погоду и маршрут. Астана: 1.6 млн туристов в 2025 году, вторая самая холодная столица мира |
| 10 | Доверие, приватность, оценка | Ничего не храним, факты считает код, валидатор, 15 сценариев и 12 автоматических проверок | Закон РК о ПД № 94-V (локализация ПД), Закон РК об ИИ (маркировка ИИ-контента), OWASP LLM01 (prompt injection) |

## Ограничение по ресурсам
Разработка идёт на ноутбуке с 16 ГБ RAM. Тяжёлые шаги пайплайна запускаются с жёстким лимитом памяти (`systemd-run -p MemoryMax=…`). Рантайм API укладывается в ~1.3 ГБ, а при `EMBED_MODEL=e5-small` или `off` — в 0.3–0.6 ГБ.
