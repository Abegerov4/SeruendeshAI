# Обновление базы Smart City — итоговый список работ

Составлено: 19 октября 2026 года.

Целевой срок: **20 октября 2026 года, 10:00, Asia/Almaty (Астана)**.

Этот документ фиксирует согласованный объём работ. После обсуждения пользователь разрешил выполнение, сбор и локальную публикацию. Состояние выполнения и точные показатели приводятся в отдельном итоговом отчёте.

## 1. Проверить весь каталог

- [ ] Зафиксировать исходную версию и резервную копию базы.
- [ ] Составить очередь проверки всех записей, включая записи вне текущей выдачи рекомендаций.
- [ ] Для каждой записи определить применимые поля: например, меню для заведения питания, интерактивные занятия для музея, игровые возможности для площадки.
- [ ] Для каждой записи сохранить результат обхода: найдено подтверждение, есть противоречие, не найдено после завершённого поиска, проверка не завершена из-за ошибки или ограничения доступа.
- [ ] Измерить покрытие по категориям и отдельным полям до и после обновления.

Исходный масштаб по последней проверке: 14 006 записей в полном каталоге, 2 750 мест в текущем наборе рекомендаций. Эти числа необходимо пересчитать перед запуском.

## 2. Проверить идентичность, существование и состояние мест

- [ ] Сопоставлять конкретный филиал по названию, адресу, координатам и доступным контактам.
- [ ] Разделять филиалы одной сети; общие сведения сети применять только при подтверждённой области действия.
- [ ] Проверить координаты, принадлежность Астане, адрес, корпус, этаж и вход, когда они опубликованы.
- [ ] Найти дубли, переименованные и переехавшие места; сохранить связь между старой и новой записью.
- [ ] Уточнить тип и подтип места: кофейня, кафе, столовая, ресторан, музей, площадка и другие.
- [ ] Проверить записи категории `other`, среди которых могут находиться полезные места, пропущенные поиском.
- [ ] Различать рабочие состояния: работает, временно закрыто, закрыто навсегда, переехало, статус спорный или неизвестный.

## 3. Удалить неподходящие записи из рабочего каталога

Пользователь разрешил удалять закрытые компании и филиалы, по которым не удалось найти данные.

Для исполнения используется следующий критерий:

- [ ] Удалить из рабочего каталога филиалы с подтверждённым постоянным закрытием.
- [ ] Удалить филиалы, для которых после завершённого поиска по установленному набору доступных источников не найдено актуальное подтверждение существования именно этого филиала.
- [ ] Спорные совпадения и противоречивые статусы исключить из рекомендаций до разрешения противоречия; сохранить отдельную очередь проверки.
- [ ] Удаление отражать согласованно в поиске, рекомендациях, карте, справочнике ориентиров и индексах.
- [ ] Сохранить в архиве исходную запись, стабильные идентификаторы, причину, ссылки на доказательства и дату исключения. Последующие обновления должны учитывать эти решения.

«Не найдено» означает отсутствие подтверждения после завершённой проверки, а не доказательство закрытия. Эти причины учитываются отдельно в отчёте. Ошибка загрузки, блокировка, исчерпанный лимит или отсутствие доступа к источнику означают незавершённую проверку. Отсутствие отдельного поля — часов, розеток или меню — сохраняется как неизвестное значение.

Для общественных объектов без коммерческого филиала проверяется существование самого объекта. Меню, телефон и сайт для них могут быть неприменимы.

## 4. Дополнить сведения, нужные пользователю

Все сведения добавляются при наличии подходящего источника. Название, категория и текст модели не подтверждают удобства или услуги.

| Блок | Что собрать |
|---|---|
| Время работы | Расписание по дням, перерывы, опубликованные сезонные и временные изменения |
| Контакты | Официальный сайт, телефон, страницы филиала, способы записи |
| Описание и занятия | Что представляет собой место; какие конкретные занятия, экспозиции или услуги доступны |
| Работа с ноутбуком | Розетки, Wi-Fi, столы, опубликованные правила работы с ноутбуком |
| Дети | Возрастные ограничения, игровая зона, интерактивы, пеленальный стол, условия посещения с коляской |
| Доступность | Ступени, пандус, лифт, доступный вход и туалет — отдельными признаками |
| Условия доступа | Общественный или ограниченный доступ, запись, билет, пропуск, документ, сопровождение, ограничения по возрасту |
| Среда и сезонность | Помещение или улица, укрытие, сезон работы, опубликованные ограничения при погодных условиях |
| Бытовые удобства | Туалет, места для сидения, гардероб, камера хранения, питьевая вода |
| Питание | Формат, кухня, блюда, состав и порции; цены с валютой, единицей, датой и каналом (в заведении, навынос, доставка); средние чеки и статистика сопоставимых филиалов |
| Экскурсии и транспортные услуги | Оператор, маршрут, точки посадки, места посещения и проезда мимо; билеты и льготы; отправления только при подтверждённой полной дате, включая RedBus |
| События | Название, организатор, место, даты начала и окончания, расписание, ссылка; завершённые события исключаются из текущих предложений |
| Время посещения | Опубликованная длительность или явно обозначенная оценка для конкретного занятия |
| Языки | Названия и варианты написания RU/KK/EN, доступные языки экскурсий и аудиогидов |
| Особенности посещения | Опубликованные правила фотографии, посещения с животными или багажом; ограничения для групп |

Тишина и загруженность сохраняются с основанием, временем наблюдения и пометкой «по отзывам» или другим точным типом источника. Оценка длительности посещения также отделяется от подтверждённого расписания.

## 5. Организовать проверяемый сбор

- [ ] Автоматизировать обход всего каталога с продолжением после остановки и без повторной загрузки неизменившихся страниц.
- [ ] Использовать официальные страницы филиалов и сетей, страницы принимающего объекта (например, ТРЦ), доступные карточки карт и справочники, страницы организаторов событий и меню.
- [ ] Задать перечень источников и правила достаточности проверки до массовых исключений; фиксировать, какие источники фактически проверены для каждой записи.
- [ ] Хранить для каждого факта источник, URL, дату получения, дату проверки, дату обновления источником, если она известна, и короткое подтверждение.
- [ ] Различать подтверждённое значение, явное отсутствие, неизвестное, неприменимое и противоречивое значение.
- [ ] Сохранять расхождения источников и историю изменений; не заменять их догадкой модели.
- [ ] Соблюсти ранее выбранную политику обновления: ручные подтверждения автоматически переносятся только для полностью неизменившихся записей; изменившиеся отправляются на повторную проверку, решения об исключении сохраняются.
- [ ] Подготовить повторный запуск обновления и очередь устаревающих фактов. Периодичность проверки разных полей определить по источникам и результатам первого обхода.
- [ ] Соблюдать существующий общий предел расходов на LLM/embeddings **$0,10**; массовое обновление не предполагает увеличения этого лимита. Платные источники и новые подписки требуют отдельного согласования.

## 6. Подключить обновлённые данные к приложению

- [ ] Обновить схему данных и проверку источников для новых полей.
- [ ] Передать подтверждённые сведения в поиск и фильтры, объяснения рекомендаций и карточки.
- [ ] Сохранить явные ограничения запроса: место соответствует условию только при достаточных подтверждениях.
- [ ] Когда существенные условия не подтверждены, сначала честно сообщить об этом и предложить ослабить запрос, как ранее выбрал пользователь.
- [ ] Публиковать обновление согласованной версией с проверенными индексами и возможностью отката.

## 7. Проверить результат и отчитаться

- [ ] Проверить сценарии ТЗ: прогулка рядом на ограниченное время, кофе и работа, досуг с ребёнком, турист перед вылетом, вечерняя активность.
- [ ] Проверить исключение закрытых, ненайденных, спорных и дублирующихся записей из всех пользовательских способов поиска.
- [ ] Проверить, что отсутствие данных не превращается в выдуманные удобства, блюда, доступность или часы работы.
- [ ] Отдельно проверить ошибки доступа к источникам: они должны сохраняться в отчёте и не имитировать завершённый поиск.
- [ ] Сформировать итоговый Markdown-отчёт и машиночитаемый список изменений: проверено, дополнено, удалено по каждой причине, осталось спорным, не удалось проверить.
- [ ] Приложить показатели заполненности по применимым полям, источники и перечень оставшихся пробелов. Полнота обхода и полнота подтверждённых сведений считаются отдельно.

## Дополнение после обсуждения

- Пользователь вернул в объём цены, средние чеки и сравнение по статистике карт. Средний чек не подтверждает цену конкретного блюда; цена доставки не доказывает цену в зале.
- Маршруты услуг, включая RedBus, входят в объём: остановки посадки отличаются от объектов, мимо которых проезжают.

Существующая пешеходная маршрутизация сохраняется. Платные интеграции дорожного движения и маршрутизации не подключаются без отдельного согласования расходов.
