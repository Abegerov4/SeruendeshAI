# Устранение аудита backend, модели и данных — 19 октября 2026

Исходный [аудит 44 проблем](backend_model_data_audit_2026-10-19.md) сохранён как исторический срез. Этот документ описывает внесённые исправления и границы их проверки. Предыдущие незакоммиченные изменения интеграции сохранены; commit/push/production deploy не выполнялись.

## Принятые решения

- Ayat — основной сервер UI; `backend/ + rag/` — отдельный сервис фото/MCP/Telegram.
- До вылета: внутренний рейс 120 мин, международный/неизвестный 180 мин; дополнительно дорога и 15 мин неопределённости. Время прибытия в аэропорт отличается от времени вылета.
- Модель выбирает места; фактические причины, действия, часы и длительность формирует код. Свободные идеи отдельно отмечены как ИИ.
- Достаточный объём ручной проверки:30 мест, по 6 для прогулки, кафе/работы, ребёнка, туриста и вечера. Проверка источника не означает осмотр на месте.
- Свежая страница конкретного владельца/ТРЦ приоритетнее старого OSM/CityPass; спор между справочниками остаётся unknown.
- При refresh подтверждения переносятся только для полностью неизменившихся записей. Изменившиеся подтверждения ждут проверки и сохраняются в истории. Карантин сохраняется всегда.
- Внешняя почта отключена по решению пользователя. Лимит платных вызовов$0,10 применяется через общий постоянный ledger и атомарное резервирование до отправки.

## Запуск и эксплуатация

```bash
docker compose up --build
# http://127.0.0.1:8001 — основной UI/API
# отдельный backend: docker compose --profile secondary up --build
```

Шаблонный профиль не требует ключа. Для LLM включаются ключ/модель и `READINESS_PROFILE=llm`; health сначала configured, затем ok только после успешных рабочих вызовов обеих ролей. Прогрев выключен по умолчанию. Ключи не копировались в репозиторий или отчёты.

При обновлении старые подписанные cookie потребуют нового входа. Новые сессии сохраняются в БД и переживают restart. SQLite volume должен сохраняться; production DB и SMTP настраиваются для конкретной целевой среды. Активный bundle не редактируется; новые данные проходят stage/quality gates/promote, затем runtime перезапускается. Dense-индекс всегда перестраивается для точного документного view либо честно отключается.

Использованы установленные навыки systematic-debugging, brainstorming, writing-plans, subagent-driven-development, test-driven-development, verification-before-completion, requesting-code-review, planning-with-files, openai-docs и agent-browser. Дополнительная установка навыков не потребовалась. Независимые ревью нашли дополнительные дефекты; они исправлены до окончательной проверки.
