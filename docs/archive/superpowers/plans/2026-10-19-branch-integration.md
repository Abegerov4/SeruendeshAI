# Локальная интеграция актуальных веток в big-data

**Goal:** Подключить актуальные совместимые компоненты из других веток, сохранить полную Data/RAG-базу и проверить живую локальную цепочку UI → API → поиск.

**Architecture:** Основной `backend/ + rag/` остаётся. Новый frontend из `origin/ayat@4e0b503` использует более богатый API Ayat; его сервер переносится в `ayat_backend/` с отдельным namespace. Адаптер читает канонический `data/processed/pois.json`, не перезаписывая его: досуговые POI становятся рекомендациями, прочие — ориентирами. Оба runtime запускаются отдельно.

**Spec:** запрос пользователя: взять актуальные версии из других веток и протестировать; менять только `big-data`, без push. Предыдущий опубликованный checkpoint `5a08f6f`.

## Ограничения

- Не делать commit/push/merge и не перемещать другие локальные ветки. Сравнить local heads до/после; remote tracking refs обновляются только fetch.
- Не менять основной checkout Aslan. Сохранить SHA канонического pois.json и всех текущих processed-файлов.
- Не возвращать старую базу/код из feature/data-rag, qa, backend: эти изменения уже интегрированы или заменены более новыми.
- Только локальные тестовые аккаунты и SQLite; LLM, embeddings, погода, SMTP и tracing отключены. Внешние платные вызовы и deployments не запускаются.
- Использовать отдельное Python-окружение внутри worktree. Не устанавливать зависимости в основном checkout.

## Проверяемые риски

- API основного backend отличается от нового UI: маршруты/аккаунты требуют нового совместимого runtime, а не молчаливого усечения полей.
- Неполные атрибуты источника не становятся подтверждением Wi-Fi/пригодности детям.
- Старые embeddings не используются для другого состава/порядка POI.
- Сохранения после reload/logout/login не приводят к падению React и не переходят между аккаунтами.
- Тесты используют временную БД и не запускают LLM, модели, SMTP или публичное развёртывание.
