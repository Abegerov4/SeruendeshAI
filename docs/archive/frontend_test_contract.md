# Контракт проверяемости UI

Это предлагаемые стабильные hooks для Frontend, а не уже существующий интерфейс. До появления UI проверки `tests/test_ui.py` остаются NOT RUN. Наличие hooks не заменяет доступные подписи, роли, управление клавиатурой и ручную проверку.

| `data-testid` | Назначение |
|---|---|
| `query-input` | Поле запроса, доступное как textbox |
| `submit-query` | Кнопка отправки |
| `geolocation-button` | Получение координат только по нажатию |
| `recommendation-card` | Карточка, у каждой `data-poi-id` |
| `map` | Область карты |
| `used-context` | Видимый контекст запроса |
| `open-status` | Статус часов внутри карточки |
| `source-label` | «Данные POI» / «Идея ИИ» внутри карточки |
| `error-message` | Понятное сообщение об ошибке |
| `empty-state` | Пустая выдача и объяснение, что делать дальше |

Команды: `python -m pip install playwright`, `python -m playwright install chromium`, затем запустить Frontend и `python -m pytest --live-ui --ui-url http://127.0.0.1:5173 -m live_ui`.

Большинство UI-проверок подменяет только внешний ответ API: они проверяют **настоящий интерфейс**, но не качество RAG/LLM. Отдельный `test_real_frontend_backend_path` требует одновременно `--live-ui --live-api --pois data/processed/pois.json` и проверяет настоящую цепочку. Не выдавать изолированный UI-прогон за полноценный E2E.

Вручную до защиты: карта↔карточка; отказ GPS; ответ A пришёл позже B и не затёр его; повторный клик не создаёт лишние запросы; клавиатура/focus; экран 360px; длинные названия; RU/KK/EN; проблемы тайлов карты; округление GPS, клика по карте и выбранного ориентира; отсутствие координат в хранилищах/телеметрии/ошибках. Точные селекторы и состояние загрузки уточняются с Frontend без ослабления наблюдаемого поведения.
