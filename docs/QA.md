# Как мы тестируем SeruendeshAI

Каждый push в `main` и `ayat` запускает в GitHub Actions ([ci.yml](../.github/workflows/ci.yml)) все наборы ниже и сборку Docker-образа. Раз в неделю отдельный workflow собирает данные заново и открывает PR на проверку ([data-refresh.yml](../.github/workflows/data-refresh.yml)).

| Набор | Что проверяет | Команда | Результат 19.10 |
|---|---|---|---|
| Бэкенд | Контракт API, поиск и ранжирование, часы работы на момент прихода, маршруты по графу улиц, точка старта (GPS, ориентир, дом, текст), еда без выдумок, приватность и округление, prompt injection, Telegram-вебхук | `cd backend && uv run pytest -q` | 525 passed |
| Сценарии | 15 сценариев × 12 автоматических проверок, включая пять из задания | `make eval` (шаблоны), `make eval-llm` (LLM + LLM-судья) | 170/170 в обоих режимах, [EVAL_RESULTS.md](EVAL_RESULTS.md) |
| QA-набор команды | Golden-сценарии, схема и границы датасета, безопасность, языки, время и полночь, метрики, readiness | `python -m pytest tests --pois data/processed/pois.json --live-backend --live-rag -q` | 373 passed; 119 пропущены, им нужен запущенный API, UI или PostgreSQL |
| Данные | Сборка каталога, источники и атрибуция, часы, дубли | `python -m pytest data/tests -q` | в CI |
| RAG-модуль | Поиск по каталогу команды | `python -m unittest discover -s rag/tests` | 7 passed |
| Качество поиска | Recall и nDCG на размеченном наборе | `python -m rag.evaluate eval/datasets/astana_retrieval_v2.json --mode bm25` | в CI |
| Telegram-бот | Сценарии диалога, кнопки, языки | `python -m pytest bot/tests -q` | 12 passed |
| Фронтенд | Планировщик, участки маршрута, сборка | `cd frontend && npm test && npm run build` | 17 passed, сборка OK |
| Фото карточек | Хранилище S3 (SeaweedFS) | `python -m pytest -c backend/pyproject.toml infra/photos/tests` | 7 passed |

## Проверка продакшена

После каждого деплоя прогоняем на https://seruendesh.site:

- `/api/health`: число мест, событий, состояние LLM;
- сценарии из задания (Mega Silk Way, EXPO, турист перед вылетом, казахский, маршрут от AITU до ботсада, с ребёнком, на машине) с фиксированным временем, чтобы музеи были открыты;
- браузерную проверку в Playwright: ответ приходит, на карте участки маршрута со стрелками, кнопка «Найти с этими условиями» отправляет ровно один запрос, «Маршруты» работают без геолокации после выбора старта, в консоли нет ошибок.

## Что автоматические тесты не доказывают

- Что часы работы в реальном мире совпадают с данными. Поэтому у часов есть источник и дата проверки, а неизвестные часы так и подписаны.
- Качество текста объяснений. Его оценивает LLM-судья (1–5) и человек; судья нашёл неподтверждённые утверждения в 3 ответах из 23.
- Поведение на реальных прогулках. Следующий шаг — пилот с пользователями.

Сценарии и ограничения подробно: [TEST_SCENARIOS.md](TEST_SCENARIOS.md). Ранние черновики QA от 18 октября: [archive/](archive/).

## Изменения 20 октября

Добавлен `npm run test:browser` в `frontend/`: Playwright проверяет первый запуск без запроса GPS, выбор точки старта, время выбранной альтернативы, изоляцию аккаунтов, поздний ответ после выхода, откат сохранения, повтор поиска, мобильные вкладки и поле адреса при клавиатуре. API в этих браузерных тестах подставной; реальная модель и провайдеры ими не проверяются. Workflow устанавливает Chromium и запускает этот набор после сборки фронтенда.

Результаты новой локальной проверки, команды воспроизведения и ограничения: [VALIDATION.md](handoff-claude/2026-10-20/VALIDATION.md). Прежние результаты в таблице выше относятся к 19 октября.
