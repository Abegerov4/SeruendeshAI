Тест генерации подставляет намеренно неверный ответ модели и проверяет реальную сборку финального ответа.

## Команды

```bash
cd backend
uv run pytest -q
OPENAI_API_KEY='' LLM_ENABLED=false EMBED_MODEL=off WEATHER_ENABLED=false \
  DATABASE_URL=sqlite:////tmp/seru-validation.db \
  uv run python eval/run_eval.py --no-llm \
    --out /tmp/seru-validation.md --results-out /tmp/seru-validation.json

cd ../frontend
npm ci
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

Командный набор запускался через `python -m pytest data/tests bot/tests tests --pois data/processed/pois.json --live-backend --live-rag -q`. Недостающие зависимости сборщиков установлены во временную среду вне репозитория; 119 пропусков включают отдельные live API/UI/PostgreSQL проверки.

В локальной среде использовался готовый `backend/.venv/bin/python`. Для Playwright задан `PLAYWRIGHT_CHROMIUM_EXECUTABLE` на установленный Chromium; конфигурация также умеет использовать стандартный браузер, устанавливаемый Playwright. CI выполняет `npx playwright install --with-deps chromium` перед браузерными тестами.

## Границы проверки

- Playwright использует подставные API-ответы. Реальные cookie, SQL и валидация серверного API проверяются pytest; это два отдельных уровня, не полный сетевой end-to-end.
- Мобильная клавиатура моделируется изменением viewport. Проверка на физических телефонах остаётся задачей команды.
- Новый платный LLM benchmark не запускался. Шаблонные 170/170 нельзя представлять как оценку качества генерации.
- Docker image и GitHub runner в этой итерации не запускались. Изменение CI добавлено в конфигурацию, но удалённый статус появится после push.
- Локальный сценарий S4 теперь ожидает пустой список и нулевой бюджет. Старые отчёты со сценарием «2 часа до вылета → прогулка» относятся к прежней логике.
- Реальные часы, состояние входов, пригодность для детей и качество переводов требуют проверки источников и людьми.
