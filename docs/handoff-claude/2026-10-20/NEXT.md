# Следующие задачи перед сдачей

## Клод и бэкенд

1. После развёртывания проверить фактический `FLIGHT_UNKNOWN_BUFFER_MIN`: переменная окружения может переопределить новый default 180. Проверить RU/KK/EN: два часа до вылета → нет прогулки; внутренний рейс через пять часов и 30 минут на кофе → ограниченный план; быть в аэропорту через два часа → отдельный дедлайн прибытия.
2. Провести свежий LLM-прогон и ручную оценку 20–30 новых запросов. Проверить не только JSON/количество мест, но и обоснованность каждого действия, отрицания, уточнения, язык и соответствие конечному расписанию. Исторические 170/170 не доказывают эти свойства.
3. Для альтернатив улучшать конкретность действий через подтверждённые факты. Не возвращать инструкции «затем перейди к…», если `route` отсутствует. Для настоящего маршрута текст должен ссылаться только на остановки конечного расписания в правильном порядке.
4. Сверить проверенные вручную места с активным продуктовым снимком: большой командный каталог и используемый сервером набор отличаются. Проверить часы, доступность, источники фото и описаний у мест трёх демонстрационных сценариев.
5. Проверить readiness реального LLM-профиля и актуальность provider proof отдельно от доступности шаблонного fallback. Один `ready=true` в профиле template не подтверждает модель.
6. При необходимости добавить обновление сохранённой карточки по POI ID. Сейчас это снимок; устаревшие часы не должны выглядеть как новая проверка.

## Codex и интерфейс

1. Проверить реальные iPhone Safari/PWA и Android Chrome: клавиатуру для чата и адреса, безопасные отступы, переход в навигатор, возврат из него, поворот телефона.
2. При расширении браузерных тестов добавить один сквозной сценарий с настоящим локальным API и БД. Текущие Playwright-тесты используют API fixtures; серверный контракт сохранений проверяется отдельно pytest.
3. Если нужен перенос гостевых сохранений в аккаунт, предложить явный импорт. Не смешивать владельцев и не сохранять старое состояние после выхода.
4. По результатам тестирования с людьми упростить элементы, которые они не находят. Провести пять коротких сессий без подсказок.
5. После функциональной стабилизации разобрать накопленные CSS-переопределения и разделить крупный JS bundle. Это не блокирует текущую сборку.

## Сдача и демонстрация

- Записать и загрузить обязательное YouTube-демо. Добавить реальную доступную ссылку в `docs/submission.json` и README. Сейчас `demo_url` пустой.
- Обновить PDF/PPTX по текстовому сценарию `docs/PRESENTATION.md`: не показывать длительную прогулку за два часа до вылета. Прорепетировать выступление на 5–7 минут.
- Подготовить видео как резерв, но явно отличать запись и живое демо. Проверить публичные ссылки в режиме без авторизации.
- После решения о публикации развернуть коммит и отдельно прогнать сайт. Локальные зелёные тесты не означают, что сервер уже обновлён.
