# Этика, приватность и достоверность

Критерий №6 жюри: «минимизация хранения точных координат пользователей, прозрачность работы с данными, работа с недостоверной информацией». Ниже то, что реализовано в коде, а не только задумано.

## 1. Геолокация пользователя

| Мера | Где в коде |
|---|---|
| Локация запрашивается только по нажатию «Моё местоположение» (браузер), без автозапроса | фронтенд |
| Клиент округляет координаты до 3 знаков (~111×70 м на широте Астаны) **до отправки** | фронтенд, `docs/API.md` |
| Сервер **округляет повторно** и не принимает точки вне Астаны: тогда пометка и просьба указать ориентир. Локацию мы не угадываем | `service._resolve_origin`, `geo.round_coord` |
| Координаты живут только в памяти на время одного запроса и никогда не пишутся в БД; в логах нет координат и IP | `service.py`, `main.py` (лог: `request_id`, язык, режим, число карточек, мс) |
| Аккаунт необязателен. Если он есть, храним только имя, email, хэш пароля (argon2) и список сохранённых мест. Сессия — подписанная httpOnly-cookie на 30 дней, сбрасывается при смене пароля. Аккаунт удаляется вместе с данными одной кнопкой | `auth.py`, `db.py` |
| Личные данные в тексте запроса (телефон, email, карта, IBAN, ИИН) маскируются **до** парсинга и LLM; пользователь видит пометку | `guards.mask_pii`, `service.recommend` |
| Режим «где я?» по фото: картинка не сохраняется. EXIF удаляется целиком, GPS из EXIF не читается. Перед ИИ фото уменьшается до 1024 px. ИИ выбирает место только из закрытого списка известных мест, а не «угадывает» адрес | `photo.prepare_image`, `photo.closed_set` |
| MCP-коннектор работает через те же защиты, что и API: маскирование ПД, вырезание инъекций, округление координат, лимит запросов | `mcp_connector.py` |
| Попытки «игнорируй инструкции…» вырезаются из запроса, тексты мест из источников передаются модели как данные в отдельном блоке | `guards.strip_injection`, `guards.wrap_untrusted` |
| **Координаты не передаются в LLM.** Модель видит только минуты пути, посчитанные кодом, и название района | `generate.card`, `generate.context_block` |
| В ответе локация показана округлённой («~ район Байтерека, округлено»), чтобы пользователь видел, что именно использовано | `used_context.location` |
| Альтернатива без GPS: ориентир в тексте («возле Mega Silk Way») или выбор из списка | `query.find_landmark_in_text`, `/api/meta` |
| Ограничитель частоты запросов держит IP в памяти 60 секунд и нигде его не пишет | `main._rate_limited` |
| Обратная связь «место закрыто» хранит только агрегированные счётчики по месту | `/api/feedback` |

Почему не только округление: по данным de Montjoye и др. (2013), 4 пространственно-временных точки идентифицируют 95% людей, и огрубление почти не помогает. Главная защита — **не хранить локацию**, и система так устроена: даже у пользователя с аккаунтом сохраняются только выбранные места, а не его перемещения.

### Законодательство РК (наше прочтение, не юридическая консультация)
- **Закон «О персональных данных и их защите» № 94-V.** Геолокацию мы на всякий случай считаем персональными данными и не храним её вовсе: только округлённая точка и только на время запроса. Данные аккаунта (имя, email) — персональные данные. Демо-стенд работает на Railway вне Казахстана, что не выполняет требование ст. 12 о хранении ПД на территории РК. Для пилота с городом БД переносится в казахстанское облако (например, PS Cloud или облако Казахтелекома). Код от этого не меняется, достаточно задать `DATABASE_URL`.
- **Закон РК «Об искусственном интеллекте»** (вступил в силу в январе 2026) требует сообщать пользователю, что ответ сгенерирован ИИ, и маркировать такой контент. У нас это:
  - видимый `disclaimer` «Ответ сформирован ИИ…»;
  - машиночитаемая метка `ai_generated: true`;
  - пометка «Идея ИИ» на сгенерированных карточках;
  - раскрытие ограничений в `notes`.
- **OpenAI API.**
  - Данные API не используются для обучения. Журналы для контроля злоупотреблений хранятся до 30 дней; это раскрыто пользователю.
  - Мы ставим `store=false`.
  - В LLM не уходят ни координаты, ни идентификаторы, только текст запроса и карточки мест.

## 2. Достоверность: не утверждать то, чего нет в данных

1. **Факты считает код, LLM их не пишет.** Расстояния, время в пути, часы работы, доступность, ссылки и адреса берутся из данных и расчётов. Валидатор вырезает из текста LLM числа с единицами («600 м», «7 минут»), время «18:00», цены, ссылки и фразы «сейчас открыто», «безопасно» ([`generate.clean_text`](../backend/app/generate.py)).
2. **Только кандидаты из базы.** LLM выбирает по меткам `c1…c10`. Неизвестный id отбрасывается, выдумать место нельзя.
3. **Часы работы с уровнем уверенности:**
   - `open` / `closing_soon` / `closed`: разобран тег OSM `opening_hours` на момент *прибытия*, а не на момент запроса. Уверенность «высокая», если данные проверены не больше года назад (`check_date`), иначе «средняя»;
   - `always`: открытая территория (парк, сквер, памятник) без указанных часов;
   - `unknown`: часов нет или строка нестандартная. Пишем «уточните перед визитом» и никогда не говорим «открыто»;
   - в праздники РК (включая перенесённые выходные, через пакет `holidays`) уверенность понижается с припиской «часы могут отличаться». Библиотека часов работы не знает переносов, мы это проверили.
4. **Честные метки источника:**
   - «📍 Данные POI»: место из собранного датасета, со ссылкой на OSM, Wikidata или Wikipedia;
   - «✨ Идея ИИ»: творческая мини-активность без фактов, координаты только у якорного места;
   - происхождение описания хранится в `description_source` (wikipedia / template / osm).
5. **Неизвестное = неизвестно.** Если в данных нет Wi-Fi, розетки или доступности, мы не говорим «нет». Удобство просто не показывается, а для розеток и «тишины» в `notes` есть явное предупреждение.
6. **Устаревшие данные.**
   - Закрытые места (`disused:*`, `was:*`, `opening_hours=closed`) исключаются при сборке.
   - Прошедшие события отбрасываются.
   - Кнопка «Сообщить об ошибке» накапливает сигналы для следующего обновления.
   - Снимок данных обновляется каждую неделю.
7. **Prompt injection.** OSM и Wikipedia может редактировать кто угодно, поэтому:
   - описания в карточках обрезаются до 260 символов, ссылки удаляются;
   - описания с «ignore previous / игнорируй / system prompt» отбрасываются;
   - системный промпт прямо говорит, что текст карточек — данные, а не инструкции;
   - на выходе строгая схема и валидатор, ссылки выводятся только из базы;
   - сценарий S12 в тестах проверяет, что попытка вытащить промпт не проходит.

## 3. Безопасность пользователя (правила в коде, не в промпте)

| Ситуация | Правило |
|---|---|
| С ребёнком | Бары, ночные клубы и кальянные исключаются полностью. После 21:00 показывается напоминание о ст. 132 КоАП РК (несовершеннолетние в развлекательных заведениях после 22:00 только со взрослыми) |
| Темно (по закату, `astral`) | Парки, скверы и площадки без `lit=yes` не предлагаются. Приоритет у работающих заведений |
| Холод и ветер (Open-Meteo, «ощущается») | ≤ −10°C: на улице до ~20 мин. ≤ −20°C: до ~10 мин. ≤ −30°C или порывы ≥ 20 м/с: только помещения и **такси**. С ребёнком правило на ступень строже |
| «Без ступенек» | Исключаются места с `wheelchair=no`. Доступность показывается только если она есть в данных (`yes` / `limited`), иначе «нет данных» |
| Дедлайн (рейс/поезд) | Код считает дорогу обратно на такси и запас 15 мин, у карточки есть «выйти до HH:MM», плюс честная оговорка про регистрацию |
| Слово «безопасно» | Запрещено: валидатор его удаляет, потому что гарантировать безопасность мы не можем |

## 4. Прозрачность для пользователя
Блок «Что я учёл» (`used_context`) показывает:
- откуда взята локация и с какой точностью;
- локальное время, праздник, темноту и погоду (с источником);
- бюджет, режим, скорость и радиус;
- что система поняла из текста и каким парсером;
- какие фильтры ослаблены;
- воронку «всего → достижимо → после фильтров → показано»;
- источники данных с датой сборки.

Блок `considered` показывает, какие места отброшены и почему: «закрыто к моменту прихода», «не для детей», «неосвещённая территория в тёмное время».

## City Insights (страница «Для города», 19.10)
- Хранятся только счётчики: ячейка ≈1 км (0,01°), интервал 3 часа, тип запроса (категория/потребность), был ли хороший ответ рядом. Текст запроса, точные координаты, IP и пользователи не сохраняются (`backend/app/insights.py`, таблица `demand_counts`).
- Публикуются только значения, за которыми стоит не меньше K = 5 запросов (k-анонимность); остальное показывается одной суммой «скрыто».
- Счётчики старше 90 дней удаляются. Ключи лимитера запросов — HMAC с секретом сервера, а не хеш IP.

## Дом пользователя и фото мест (19.10, вечер)
- **Дом на сайте** хранится только в браузере пользователя (`localStorage`), округлён до ~100 м. На сервер он уходит только в том запросе, где прогулка начинается от дома (выбран «🏠 Дом» или в тексте «от дома / рядом с домом»), и нигде не сохраняется. В статистику «Для города» такие запросы не попадают.
- **Поиск адреса дома** идёт через наш справочник, затем через OpenStreetMap Nominatim в границах Астаны. Мы не логируем введённый адрес, а Nominatim видит запрос по своей политике использования.
- **Дом в Telegram-боте** хранится в таблице `bot_homes` по солёному хешу пользователя (без id Telegram), округлён до ~100 м. Команда `/forget` удаляет его.
- **Фото мест** — либо файлы Wikimedia Commons со свободной лицензией (автор и лицензия подписаны, файл выбран по названию места рядом с точкой), либо картинка, которую заведение само публикует для превью ссылок на своём сайте (`og:image`). Такие фото подписаны «Фото с сайта <домен>» и ведут на сайт. Мы ничего не перезаливаем, логотипы и мелкие картинки отбрасываются, у мест без фото — подписанная иллюстрация или обложка категории.
