# SeruendeshAI: ИИ-помощник по прогулкам в Астане

> Хакатон **Build with AI**, задача 1 от **НИЦ Smart City**: RAG-система, которая в реальном времени подсказывает, куда сходить и что сделать рядом, с учётом локации, времени, погоды и предпочтений.

**«Я возле Mega Silk Way, у меня час. Куда?»** Система отвечает 1–3 конкретными местами. Для каждого:
- сколько идти (по реальному графу улиц) и сколько пробыть;
- **почему** это подходит именно сейчас и **что там делать**;
- статус часов работы с уровнем уверенности;
- метка источника: «Данные POI» или «Идея ИИ».

При необходимости строится мини-маршрут на карте. Блок «Что я учёл» показывает все использованные данные.

| | |
|---|---|
| Демо | **https://seruendesh.site** (резерв: https://seruendesh-production.up.railway.app) |
| Данные | **2307 мест Астаны**, собранных автоматически: OSM + Overture + Wikidata/Wikipedia; события Ticketon/Sxodim; погода Open-Meteo |
| RAG | Сначала структурный поиск (граф улиц, часы работы, безопасность) → гибрид BM25 + e5 → LLM `gpt-6-luna` выбирает и объясняет → валидатор |
| Языки | RU / KK / EN |
| Качество | 15 сценариев × 12 автоматических проверок: **170/170**, ответ ~3.5 с ([EVAL_RESULTS](docs/EVAL_RESULTS.md)) |
| Приватность | Локация округляется до ~100 м, не хранится и не передаётся в LLM |

## Быстрый старт

Нужны Python ≥ 3.12 и [uv](https://docs.astral.sh/uv/). Ключ OpenAI необязателен: без него работает шаблонный режим.

```bash
cp .env.example .env            # вписать OPENAI_API_KEY
cd backend
uv sync                         # зависимости рантайма + dev
uv run uvicorn app.main:app --port 8000
```

- Swagger: http://localhost:8000/docs
- Проверка: `curl localhost:8000/api/health`
- Первый запуск один раз скачивает модель эмбеддингов (~560 МБ). Режим без неё: `EMBED_MODEL=off`, тогда поиск только по BM25 и ~0.3 ГБ RAM.

Пример запроса:

```bash
curl -s localhost:8000/api/recommend -H 'content-type: application/json' -d '{
  "query": "Я сейчас возле Mega Silk Way, хочу прогуляться 30–60 минут — что посоветуете?",
  "lang": "ru"
}' | python -m json.tool
```

Фронтенд (React + Vite) лежит в `frontend/`, инструкции в [frontend/README.md](frontend/README.md). Укажите `VITE_API_URL=http://localhost:8000`.

Docker: `docker compose up --build` (из корня, использует `.env`): один контейнер отдаёт и API, и собранный фронт.

Фото карточек в SeaweedFS/S3: [запуск, загрузка и резервное копирование](docs/CARD_PHOTOS.md).

Хостинг: Railway (проект `seruendesh`) собирает корневой `Dockerfile` (`railway.json`, healthcheck `/api/health`); ветки `main` и `ayat` содержат одно и то же приложение. Деплой: `make deploy`.

### Команды

```bash
make test        # тесты бэкенда (без ключа)
make eval        # 15 сценариев в шаблонном режиме (backend/eval)
make eval-llm    # те же сценарии с LLM + LLM-as-judge
make data        # полный автоматический сбор данных: fetch → build → graph → embed → events
make contract    # выгрузить OpenAPI и примеры ответов для фронтенда
```

## Как это работает (кратко)

```
запрос + фильтры + локация (~100 м)
  ├─ правила (язык, время, дети, кофе, ночь…)      ┐
  ├─ LLM-разбор gpt-6-luna → строгий JSON          ├─ параллельно
  ├─ погода Open-Meteo, праздники РК, темнота      │
  └─ эмбеддинг запроса (e5-large, локально)        ┘
→ точка старта (ориентир в тексте / GPS / список)
→ достижимость: Dijkstra по пешеходному графу OSM (мосты через Есиль!)
→ жёсткие фильтры в коде: часы при прибытии, дети, доступность, темнота, мороз, дедлайн рейса
→ скоринг: категория + BM25/e5 (RRF), близость, нужды, часы, контекст, популярность → MMR
→ мини-маршрут: перебор порядков 2–3 точек с проверкой часов
→ LLM выбирает 1–3 из карточек c1..c10 и пишет «почему» / «что делать»
→ валидатор: только известные id; числа, часы и «открыто сейчас» вырезаются; иначе шаблон
```

Подробно в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Структура репозитория
```
backend/          продукт: FastAPI (API, MCP-коннектор, режим по фото, аккаунты) + раздача фронтенда
  app/            поиск, ранжирование, маршруты, LLM, валидатор, защиты
  pipeline/       сбор снимка, который отдаёт API (OSM, Overture, Wikidata, Wikipedia, CityPass, фото, граф, эмбеддинги)
  eval/           15 сценариев и харнесс оценки (проверки + LLM-as-judge)
  tests/          483 теста: контракт, безопасность аккаунтов, время, фото, MCP, исправления аудита
frontend/         интерфейс (React + Vite, маскот Серу)
bot/              Telegram-бот — тонкий клиент API
data/processed/   снимок API (pois.jsonl, газеттир, граф, эмбеддинги, манифест) и каталог команды (pois.json, ревью)
data/             каталог команды на 14 тыс. мест с происхождением, ревью и проверками (сбор, тесты)
rag/              модуль гибридного поиска команды (BM25 + Chroma) и его оценка
tests/            QA-набор команды: контракт, безопасность, golden set, данные, RAG
eval/             golden set на 64 сценария, судья, метрики, шлюз готовности, отчёты прогонов
docs/             концепция, архитектура, данные, этика, сценарии, презентация, API, MCP, аудиты
team/             роли и контракты команды
```

Как сведены ветки и что взято из каждой — [docs/INTEGRATION.md](docs/INTEGRATION.md).

## Ограничения
Честно описаны в [docs/TEST_SCENARIOS.md](docs/TEST_SCENARIOS.md#ограничения). Главные:
- часы работы есть у ~20% мест;
- рейтингов в открытых данных нет;
- розетки и «тишина» почти не размечены;
- пешеходный граф покрывает центр, ЭКСПО и НУ;
- время на машине оценивается эвристикой, без пробок в реальном времени.
